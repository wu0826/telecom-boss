# 系統健康與受控復原工作區

## 目的與權限

後台 `#system` 是唯讀工作區，僅開放給具有 `access.manage` 或 `audit.read` 的工作階段。它讀取既有的 `GET /api/v1/health`，只呈現服務狀態、兩個資料庫的固定狀態和 ISO 8601 檢查時間；不新增健康端點、不執行查詢參數，也不寫入資料。

頁面只會顯示「正常」、「暫時無法使用」或「狀態未確認」。它不輸出資料庫路徑、備份位置、堆疊、帳密、權杖、連線資訊或原始例外內容。無權角色不會看到導覽項目。

## 受控復原流程

這個工作區不是復原工具；唯一可操作的控制是重新讀取健康狀態。它提供下列經審核的流程提醒：

1. 先停止服務，並只由已授權操作人員處理。
2. 使用新的、可驗證的備份目的地執行 migration。畫面只顯示不含路徑的佔位指令：

   ```powershell
   npm run db:migrate -- --metadata-backup <新的受驗證中繼資料備份> --telecom-backup <新的受驗證營運資料備份>
   ```

3. 需要回復時，先核准目標與備份，依 [README 的資料庫備份與回復](../README.md#資料庫備份與回復) 在受控 PowerShell 工作階段操作。
4. 回復後先執行 `npm test`，再檢查健康端點；若仍異常，停止後續動作並交由維運人員處理。

頁面沒有建立備份、Migration、回復、下載、上傳或刪除按鈕；它也不會把操作指令送到瀏覽器或伺服器執行。

## 驗證邊界

健康端點正常時，兩個資料庫卡片皆顯示「正常」。端點失敗時，工作區會清除先前卡片並顯示通用、可行動的錯誤訊息；不保留舊健康資料，也不揭露失敗原因。桌面瀏覽器驗證使用隔離暫存資料庫，不接觸正式資料、遠端 VM 或 CSMU。
